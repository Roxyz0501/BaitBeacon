# Bait Beacon 1.0.0.3 review

Reviewed all runtime source, localization, saved-list parsing, bundled bait relationships, configuration persistence/lifecycle and packaging.

## Fixes

- Required bait resolution previously treated any resolved prerequisite as success, hiding missing target bait or other prerequisites. Every prerequisite must now resolve as well as the target route; known bait is still retained. Fish 8760 (bait 2625, prerequisite 5008 using bait 2603) reproduces both partial-data cases. Replacing the resolver with the previous release source makes the new regression fail.
- Structurally invalid saved-list rows could replace a valid snapshot with empty or incomplete data. Invalid names, item arrays and enabled-item flags now reject the entire update; the last valid snapshot remains available. A valid empty array still clears the list. Replacing the reader with the previous release source makes the new null-row regression fail. Older lists without EnabledItems remain supported.
- The shared inventory page guard excluded retainer pages 6 and 7, including items physically stored there after sorting. Bounds now follow each container: player 4, retainer 7, saddlebag 2. Negative sorted indices are rejected. Counts were cross-checked against FFXIVClientStructs InventoryType; native placement remains unverified.
- Font glyph coverage was frozen at startup. New names/folders now add BMP glyphs before the next font Push; handles are replaced only when coverage changes and never while pushed. Failed handle creation disposes partial replacements and retains existing handles. Supplementary-plane emoji are not added by this BMP font implementation.
- Inventory quantities previously scanned four containers for every bait row. A visible list now scans the four containers once and aggregates all relevant quantities; an empty bait set skips the scan. This reduces calls from 4N to 4 per list frame (static control-flow count, not a live-game measurement).

## Validation

- 81 offline checks passed, including 15 added regressions; Release build: zero warnings and errors.
- Existing failure, real file-lock, corruption recovery, backup retention, concurrent save, lifecycle flush and finite retry tests pass. Eight hours of unchanged settings produce zero writes; 600 edits produce one save (156 payload bytes, 148 prior-backup bytes). Unchanged saved lists perform one initial body read over 100 polls. These are measured logical bytes, not physical SSD writes.
- All 2,616 bundled recipes checked for dependency cycles: none. Data snapshot remains 2026-10-11; this review does not claim newly added game data or user overrides are supported.
- Shared tab implementation remains byte-identical to the canonical template; seven-language completeness and persistence tests pass.
- Clean isolated package contains only BaitBeacon.deps.json, BaitBeacon.dll, BaitBeacon.json, LICENSE and NOTICE. Manifest version/author/URLs and source credential/local-user-path scan pass.
- No production configuration, installed plugin DLL or game inventory was modified. Native inventory node placement, expanded retainer UI, font atlas rendering, IME/DPI, actual game lifecycle and physical SSD IO are not verified by these tests. This review does not establish the absence of all bugs.

Publication follows the project-wide continuing authorization dated 2026-10-23. GitHub connector is used for supported source/index/record operations; CLI is reserved for unsupported Release/assets and local Git synchronization.
